## 为什么需要哈希表?
### 数据查找的效率问题

- **红黑树/B树**：查找时间为对数时间复杂度 O(log n)
- **更高效的方案**：哈希表可以在理想情况下实现常数时间复杂度 O(1) 的查找

### 基本原理

1. 为所有数据分配唯一编号（哈希码）
2. 创建数组表格存储数据
3. 建立编号与数组索引的映射关系
示例表格:

| key |  0  |  1  |  2  |  3  |  4  |  5  |  6  |  7  |
| :-: | :-: | :-: | :-: | :-: | :-: | :-: | :-: | :-: |
| val |  赵  |  牛  |  王  |  李  |  郑  |  萧  |  吴  |  杨  |

假如我要查找"牛"这个目标,我只需要定位到索引1即可查找到.这种通过数组索引查询的时间复杂度和数据的规模无关.

---
## 哈希冲突与解决方案
### 实际问题

1. ==理想情况下==,编号唯一,数组能容纳下所有数据.但是实际情况下,我们不可能为了存储所有的数据建立一个特别大的数组,这对内存的分配很不友好
2. 无法保证编号唯一（哈希冲突）
    

### 解决方案

1. **拉链法**：
    - 使用有限长度的数组
    - 冲突元素通过链表连接
示例表:

| key |  0  |  1  |  2  |  3  |  4  |  5  |  6  |  7  |
| :-: | :-: | :-: | :-: | :-: | :-: | :-: | :-: | :-: |
| val |  赵  |  牛  |  王  |  李  |  郑  |  萧  |  吴  |  杨  |
|     |  孙  |     |     |     |     |     |     |     |
 允许编号适当重复,通过==数据自身==进行区分
"孙"和"赵"的编码都是0,这时可以通过对比数据本身来进行区分和查找

## 数据结构以及相关算法实现

### 核心数据结构
- 节点类
```Java
static class Entry{  
    int hashKey;    //哈希码  
    Object key;     //键  
    Object value;   //值  
    Entry next;  
  
    //构造函数  
    public Entry(int hashKey, Object key, Object value, Entry next){  
        this.hashKey = hashKey;  
        this.key = key;  
        this.value = value;  
        this.next = next;  
    }  
}
```
通过节点类,就相当于链表的准备工作完成

- 数组
通过数组存放链表的头结点,后续可以通过对应的头结点来访问到该链表内的内容
```Java
//数组存放的是链表头结点,大小为2的正整数次方  
Entry [] table = new Entry[16];  
//元素个数,初始值为0  
int size = 0;
```

- 存储规则-->取模运算

哈希码和数组索引的关系,我们可以通过取余来进行定位,如我要存键值对为(100, "张")的元素,这时就可以通过取模的运算(将hashKey当做被除数,数组长度作为除数)来定位这个键值对的位置-->100%8=4, 所以这个数据的存储位置就是对应的索引4. 

也可以将取模运算换做性能更好的按位与运算,前提是将数组长度设置为2的正整数次方.-->hashKey&(数组长度-1)

### 哈希算法(摘要算法/散列算法)
概述:目前实现的哈希表还存在一个问题.在使用增删改查的方法的时候,总是需要一个参数-->哈希码,通过手动提供参数很难保证不冲突,这时我们就需要一个算法来为我们==提供一个很少冲突的哈希码==.这个算法被称之为哈希算法

- 常见的哈希算法:

|   算法    |  输出长度  | 安全性 |  适用场景   |
| :-----: | :----: | :-: | :-----: |
|   MD5   | 128bit | 已破解 |  文件校验   |
|  SHA-1  | 160bit | 已破解 |  兼容旧系统  |
| SHA-256 | 256bit | 安全  | 区块链,密码学 |
| BLAKE3  |   可变   | 安全  |  高性能应用  |

在自己设计哈希算法时,有以下要点:
- 均匀性：尽可能均匀分布到数组各位置
- 高效性：计算速度快
- 确定性：相同输入产生相同输出

```Java
// 自定义哈希算法  
private int customHash(Object key) {  
    String keyStr = key.toString();  
    int hash = 0;  
    for (int i = 0; i < keyStr.length(); i++) {  
        hash = 31 * hash + keyStr.charAt(i);  
    }  
    return hash & 0x7FFFFFFF; // 确保为非负数  
}
```

### 关键方法实现
- 增删改查方法
```java
//根据哈希码获取value的值  
Object get(Object key){  
    //获取索引位置  
    int index = customHash(key) & (table.length - 1);  
    //判断索引处是否有数据  
    if (table[index] == null){  
        return null;  
    }  
    //沿着头结点进行遍历链表  
    Entry p = table[index];  
    while (p!=null){  
        if(p.key.equals(key)){  
            return p.value;  
        }  
        p = p.next;  
    }  
    return null;  
}  
  
//扩容  
void resize(){  
    //新表的容量为原数组的2倍  
    Entry [] newTable = new Entry[table.length * 2];  
    //遍历旧数组  
    for (int i = 0; i < table.length; i++) {  
        //拿到每个链表头  
        Entry p = table[i];  
        if(p!=null){  
            //拆分链表移动到新数组  
            /* 拆分规律  
              一个链表最多拆分为2个  
              如果hashKey & (table.length - 1) == i -->  
              如果hashKey & (table.length - 1) != i -->  
              */            //采用双指针进行链表拆分  
            Entry a = null;  
            Entry aHead = null;  
            Entry b = null;  
            Entry bHead = null;  
            while (p!=null){  
                if ((p.hashKey& (table.length)) == 0){  
                    if (a!=null){  
                        a.next = p;  
                    }  
                    else {  
                        aHead = p;  
                    }  
                    //分配到a  
                    a = p;  
                }  
                else {  
                    if (b!=null){  
                        b.next = p;  
                    }  
                    else{  
                        bHead = p;  
                    }  
                    //分配到b  
                    b = p;  
                }  
            }  
            if (a!=null){  
                a.next = null;  
                newTable[i] = aHead;  
            }  
            if (b!=null){  
                b.next = null;  
                newTable[i+table.length] = bHead;  
            }  
        }  
    }  
    //新数组代替旧数组  
    table = newTable;  
    threshold = (int)(newTable.length * LOAD_FACTOR);  
}  
  
  
//根据哈希码删除元素,返回删除的val  
Object remove(Object key){  
    //获取索引位置  
    int index = customHash(key) & (table.length - 1);  
    //判断索引处是否有数据  
    if (table[index] == null) {  
        return null;  
    }  
    //沿链表遍历查找要删除的节点  
    Entry p = table[index];  
    Entry prev = null;  
    while (p != null) {  
        if (p.key.equals(key)) {  
            if (prev == null) {  
                // 删除的是头结点-->将头结点指向下一个节点  
                table[index] = p.next;  
            } else {  
                // 删除的是中间或尾部节点  
                prev.next = p.next;  
            }  
            size--;  
            return p.value;  
        }  
        prev = p;  
        p = p.next;  
    }  
    // 没找到要删除的键  
    return null;  
}
```
观察上述方法的参数,我们可以发现它们都有共同的参数-->hashKey. 它的作用是定位我们接下来要查找的目标它定位在哪个索引位置.


思考:哈希表的数组大小固定死有什么弊端?
当元素个数越来越多的时候,每个索引处的链表会很长,查找的效率会降低(退化为常数时间O(n)).因此,要在数组占用空间,和对数据操作的效率中间做取舍和权衡.

### 哈希表的扩容-->用空间换时间
当数组容纳的元素个数达到一个阈值的时候,要对哈希表进行扩容.
==负载因子:== 
loadFactor = n/m ,其中n为元素个数,m为数组长度.
负载因子不宜过小也不宜过大.
```Java
//负载因子  
static final float LOAD_FACTOR = 0.75f;
```
举个例子,初始表长为8,我插入两个数据之后(loadFactor=1/4)就开始对数组扩容,会造成空间的浪费; 但是我如果是在放满了之后再去扩容,这时有的部分已经形成了链表,增删改查的效率已经受到了影响.
一般来说,loadFactor的取值为3/4. 当存入的长度达到数组长度的3/4的时候, 这时将数组的容量翻倍.

在扩容之后,某些部分的位置会发生改变,移动到表中的相应索引的位置.
拆分规律:
- hashKey & (table.length - 1) == 0 的分到一组,位置保持不变
- hashKey & (table.length - 1) != 0 的分到一组,位置移动到索引为 index+table.length的位置

```Java
//扩容  
void resize(){  
    //新表的容量为原数组的2倍  
    Entry [] newTable = new Entry[table.length * 2];  
    //遍历旧数组  
    for (int i = 0; i < table.length; i++) {  
        //拿到每个链表头  
        Entry p = table[i];  
        if(p!=null){  
            //拆分链表移动到新数组  
            /** 拆分规律  
             * 一个链表最多拆分为2个  
             * 如果hashKey & (table.length - 1) == i -->  
             * 如果hashKey & (table.length - 1) != i -->  
             * */            //采用双指针进行链表拆分  
            Entry a = null;  
            Entry aHead = null;  
            Entry b = null;  
            Entry bHead = null;  
            while (p!=null){  
                if ((p.hashKey& (table.length)) == 0){  
                    if (a!=null){  
                        a.next = p;  
                    }  
                    else {  
                        aHead = p;  
                    }  
                    //分配到a  
                    a = p;  
                }  
                else {  
                    if (b!=null){  
                        b.next = p;  
                    }  
                    else{  
                        bHead = p;  
                    }  
                    //分配到b  
                    b = p;  
                }  
            }  
            if (a!=null){  
                a.next = null;  
                newTable[i] = aHead;  
            }  
            if (b!=null){  
                b.next = null;  
                newTable[i+table.length] = bHead;  
            }  
        }  
    }  
    //新数组代替旧数组  
    table = newTable;  
    threshold = (int)(newTable.length * LOAD_FACTOR);  
}
```

## 关键问题解答:

以下内容的共同前提:数组长度必须是2ⁿ
#### 1.增删改查中为什么用位运算代替取模
- **效率**：位运算比取模运算更快
- **前提**：数组长度必须是2的幂次方
- **等价性**：`hashKey % length == hashKey & (length - 1)`
#### 2.扩容时,拆分为两个链表,一条是hashKey&原数组长度  = =0 另一条! =0
- 拆分依据：`hashKey & oldCapacity`的结果
- 目的：将元素均匀分布到新数组的两个可能位置
- 优势：避免重新计算所有元素的哈希值

## 性能优化建议

1. **初始容量选择**：根据预估元素数量设置合理初始大小
2. **负载因子调整**：根据应用场景调整（0.75是平衡点）
3. **哈希算法选择**：考虑均匀性和计算成本
4. **链表优化**：当链表过长时可转为红黑树（如Java HashMap）
